## Problem Statement

In the storage room there are many boxes with mixed personal items. When a specific
thing is needed, the current workflow is to open boxes one by one until the item is
found. This is slow, irritating, and gets worse as the number of boxes grows.

The product is not a general home inventory system. The product is a fast way to
answer: "Where are my black gloves?" or "Where is the red dress?"

## What Makes This Cool

The strongest version is an AI-first catalog for physical boxes:

1. Number the boxes and attach QR labels.
2. Open a box and take 2-3 photos of the contents.
3. AI proposes a draft list of visible items.
4. The user quickly confirms or fixes the list.
5. Later, the user searches in natural language.
6. The app returns candidate boxes and the photos where the item may be visible.

The important product shift: the app does not need to pretend it is 100% certain.
It needs to reduce the search from "open 12 boxes" to "check these 1-2 likely
boxes, with photo evidence."

## Landscape Notes

Existing products prove that the category exists:

- ToteScan sells QR labels and an app for organizing storage boxes.
- Itemtopia is a broad home inventory app for items, documents, warranties, photos,
  collections, and asset records.
- QR labels are a proven mechanism for linking a physical container to a digital
  record.

The gap for this project is focus. Existing products tend to feel like inventory
management. This project should feel like a personal search tool for a messy real
storage room.

Useful references:

- https://totescan.com/
- https://www.itemtopia.com/
- https://www.itemtopia.com/home-inventory-app/

## Premises

1. The real pain is not "I need perfect inventory." The real pain is "I do not
   want to dig through boxes when I need one thing."
2. The MVP should solve the user's own storage room before trying to serve friends,
   families, movers, or small businesses.
3. AI should create a draft from photos, but the user must confirm or correct it.
   Unverified AI output will destroy trust.
4. Number plus QR is better than QR alone. The number works for human eyes, the QR
   works for quick app navigation.
5. Search results should show candidate boxes and photo evidence, not just a single
   confident answer.
6. Visual highlighting on photos is a v2 feature. For MVP, showing the right photo
   is enough.
7. Monetization is secondary until the storage-room workflow proves useful in real
   life.

## Approaches Considered

### Approach A: Minimal Working Catalog

Summary: create boxes, assign numbers and QR codes, manually add items, search by
text.

Effort: S
Risk: Low

Pros:

- Fastest to build.
- Almost no AI risk.
- Useful enough to test whether numbered boxes and search reduce frustration.

Cons:

- Manual entry feels like bookkeeping.
- Does not deliver the main magic of "photo to searchable list."
- Easy to become another plain inventory app.

Reuses:

- Local database.
- Basic CRUD.
- QR generator.
- Full-text search.

### Approach B: AI-First MVP

Summary: create boxes with number and QR, capture 2-3 photos of contents, ask AI to
extract a draft list, let the user confirm or edit, then search by item type, color,
and natural language.

Effort: M
Risk: Medium

Pros:

- Solves the real bottleneck: entering box contents.
- Differentiates the product from ordinary inventory apps.
- Keeps trust by requiring user confirmation before search relies on AI output.

Cons:

- Needs careful UX for reviewing AI suggestions.
- Search must handle ambiguous matches and partial confidence.
- AI cost and latency need to be watched.

Reuses:

- Vision model for item extraction.
- Embeddings or semantic search for natural language queries.
- Local or simple server-backed database.
- QR generator and scanner.

### Approach C: Visual Search With Highlighting

Summary: everything in Approach B, plus object localization on the photo so the app
can draw a box around the likely item.

Effort: L
Risk: High

Pros:

- Strong demo effect.
- Helps the user verify the exact item faster.

Cons:

- More computer vision complexity.
- More false positives.
- One bad highlight can make the user distrust the whole product.

Reuses:

- Object detection or segmentation model.
- Photo annotation UI.

## Recommended Approach

Choose Approach B: AI-First MVP.

This is the right balance. It is materially better than a manual catalog, but avoids
the hardest and most fragile computer vision work. The MVP should make the storage
room searchable before it tries to make every photo smart.

## Core User Flow

### Box Selection

1. User opens the app.
2. User can select an existing box or create a new box.
3. If the user creates a new box, the app assigns a number, for example `Box 7`.
4. The app generates a QR code for the box.
5. User prints or writes the number and attaches the QR label.

### Box Editing

1. User opens a box card.
2. User sees the current list of items in that box.
3. User can add items.
4. User can delete items.
5. User can add items manually or from photos.

Manual item entry is the fallback path. Photo-based entry is the preferred path
because it reduces typing and makes the product feel useful from the first box.

### Capture

1. User opens the box.
2. User takes 2-3 photos from different angles.
3. App sends photos for item extraction.
4. AI returns suggested items:
   - black gloves
   - red dress
   - winter hat
   - USB cables
5. User reviews the suggestions.
6. User can add all suggested items or select only some of them.
7. User can delete wrong suggestions, rename unclear suggestions, or add missing
   items manually.
8. Confirmed items are added to the box.

### Search

1. User searches: `black gloves`.
2. App returns ranked candidates:
   - `Box 7`, high confidence, photo 2, matched: `black gloves`, `winter items`
   - `Box 3`, lower confidence, photo 1, matched: `gloves`
3. User opens the box card and sees the candidate photos.
4. User finds the thing without opening every box.

## MVP Scope

In scope:

- Box creation.
- Existing box selection.
- Box editing.
- Box number.
- QR generation.
- QR scanning to open a box card.
- Add 2-3 photos per box.
- Manual item add.
- Item delete.
- AI-generated draft item list from photos.
- Fast review/edit flow for AI suggestions.
- Add all suggested photo items.
- Add selected suggested photo items.
- Natural language search across confirmed items.
- Search results with candidate boxes and relevant photos.

Out of scope for MVP:

- Accounts.
- Sharing.
- Payments.
- Subscriptions.
- Family collaboration.
- Insurance records.
- Warranty/document storage.
- Exact object highlighting on photos.
- Multi-location household management.
- Marketplace or SaaS positioning.

## Search Behavior

Search should be tolerant and evidence-backed.

Examples:

- `black gloves` should match `black winter gloves`, `gloves`, and possibly
  `winter accessories`.
- `red dress` should match `red dress`, `dress`, and possibly `clothes`.
- Results should be ranked, not binary.
- Every result should show why it matched.
- Every result should show the photo candidate, because the user can verify faster
  by looking than by reading a perfect item taxonomy.

## Success Criteria

The first version works if:

1. The user's real storage room has at least 10 boxes cataloged.
2. Adding one box takes less than 2 minutes after the QR label exists.
3. Searching for a known item returns the right box in the top 2 results.
4. The user opens fewer boxes than before.
5. The user trusts the app enough to add the next batch of boxes.

## Distribution Plan

For the first personal MVP:

- Build as a local-first mobile-friendly web app or simple mobile app.
- Store data locally first if possible.
- Use a small backend only if needed for AI photo processing.
- QR codes should deep-link to box records.

For sharing with friends later:

- Export/import backup file.
- Hosted web version or packaged mobile app.
- Optional paid one-time purchase.
- Optional physical starter kit: printed QR labels plus app.

## Open Questions

1. Should the first build be mobile web, native mobile, or desktop-assisted setup
   with mobile capture?
2. How will QR labels be printed or created for the first test?
3. Which AI model should extract item lists from photos?
4. Should item extraction run immediately after each photo or after all photos are
   captured?
5. Does the user want the app to store original photos forever, or only extracted
   items plus a compressed preview?

## What I Noticed

- The strongest phrase in the session was the concrete search: `red dress` and
  `black gloves`. That is the product. Not categories, not dashboards, not asset
  management.
- Choosing "solve my own problem first" is the right constraint. It keeps the MVP
  honest.
- Choosing photo candidates before visual highlighting is also right. It protects
  trust while still making search feel smart.
